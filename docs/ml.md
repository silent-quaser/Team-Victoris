# GridGuard — ML Model Documentation

## Overview

GridGuard uses a **XGBoost binary classifier** to predict the probability
that each grid component is currently in a failed state.

This model answers: **"How likely is this component to be failed?"**

It does NOT decide: "Repair T3" — that is P3's decision engine using
Value of Information, criticality, and resource constraints.

---

## Architecture

```
Synthetic Scenarios (2000)
        ↓
Feature Extraction (ml/features.py)
        ↓
XGBoost Classifier (ml/trainer.py)
        ↓
P(failed) for each asset
        ↓
Bayesian Evidence Fusion (uncertainty/belief.py)
        ↓
Final P(failed | all evidence)
        ↓
P3 Decision Engine
```

---

## Training Data

The model is trained entirely on **synthetic data** generated by the IEEE 33-bus
simulation. Real public outage datasets (EAGLE-I, DOE-417) do not have
component-level failure labels and cannot serve as training data.

| Property | Value |
|---|---|
| Source | IEEE 33-bus pandapower simulation |
| Scenarios | 2,000 |
| Instances | 74,000 (2000 scenarios × 37 components) |
| Failure rate | ~15–25% (depends on event type distribution) |
| Split | 70% train / 15% validation / 15% test |
| Seed | 42 (reproducible) |

## Feature Vector

Each component instance is represented by 16 features:

### Asset properties

| Feature | Description | Range |
|---|---|---|
| `asset_type_encoded` | 0=line, 1=transformer zone | {0, 1} |
| `is_exposed` | Overhead / weather-exposed | {0, 1} |
| `age_factor` | Equipment age proxy | [1.0, 2.5] |
| `distance_from_sub` | Normalised distance from substation | [0, 1] |
| `previous_faults` | Historical fault count | [0, ∞) |

### Electrical state

| Feature | Description | Range |
|---|---|---|
| `loading_pct` | Current line loading fraction | [0, 1] |

### Environmental conditions

| Feature | Description | Range |
|---|---|---|
| `weather_severity` | Storm severity index | [0, 1] |
| `wind_kmh` | Wind speed | [0, ∞) |
| `rain_mm` | Rainfall | [0, ∞) |
| `temperature_c` | Ambient temperature | (-∞, ∞) |
| `load_factor` | Grid-wide load level | [0, 1] |

### Observation quality

| Feature | Description | Range |
|---|---|---|
| `scada_reading` | SCADA failure indicator | [0, 1] |
| `sensor_health` | SCADA reliability | [0.1, 1] |
| `comm_available` | Communication link status | {0, 1} |
| `technician_confidence` | Human report confidence | [0, 1] |
| `weather_evidence` | Weather-based failure evidence | [0, 1] |

### Target

| Column | Description |
|---|---|
| `true_failed` | Binary: 1=failed, 0=healthy (ground truth from simulator) |

## Model Architecture

```python
XGBClassifier(
    n_estimators=300,
    max_depth=6,
    learning_rate=0.05,
    scale_pos_weight=auto,     # Handles class imbalance
    tree_method="hist",        # Efficient histogram-based
    subsample=0.8,
    colsample_bytree=0.8,
    min_child_weight=5,
    gamma=0.1,
    eval_metric="auc",
)
```

Class weight (`scale_pos_weight`) is automatically computed from the training
data failure rate: `neg_count / pos_count`.

## Predictor API

[`ml/predictor.py`](file:///d:/GridGuard/ml/predictor.py)

### `predict_failure_probability(asset_id, line_idx, env, observation, loading_pct, previous_faults) → float`

Returns P(component is failed) ∈ [0.0, 1.0].

```python
from ml.predictor import predict_failure_probability

prob = predict_failure_probability(
    asset_id="T3_LINE",
    line_idx=2,
    env={
        "weather_severity": 0.75,
        "wind_kmh": 78,
        "rain_mm": 35,
        "temperature_c": 12,
        "load_factor": 0.82,
    },
    observation={
        "scada_reading": 0.55,
        "sensor_health": 0.80,
        "comm_available": True,
        "technician_confidence": 0.70,
        "weather_evidence": 0.68,
    },
    loading_pct=0.7,
    previous_faults=1,
)
# → 0.624 (example output for demo scenario)
```

### `predict_all_assets(env, observations, loading) → dict`

Predict failure probabilities for all 37 lines in the active network.

### Physics-based fallback

If the trained model is not available (e.g., before first run), the predictor
automatically falls back to the **storm profile physics estimate**:

```python
# No hardcoded 0.62 — computed from storm profile + loading + age
prob = storm_profile.failure_prob_line(loading_pct=0.7, is_exposed=True, age_factor=1.8)
blended = 0.6 * base_prob + 0.4 * fused_observation_prob
```

## Uncertainty Engine

[`uncertainty/belief.py`](file:///d:/GridGuard/uncertainty/belief.py)

### `update_belief(asset_id, observations, ml_prior) → BeliefState`

Fuses multiple evidence sources via weighted Bayesian update:

```
P(failed | evidence) ∝ Σ w_i × evidence_i / Σ w_i
```

| Evidence source | Default weight | Notes |
|---|---|---|
| SCADA reading | `1.5 × sensor_health × comm_factor` | Most direct signal |
| Technician report | `1.2` | High-trust human judgment |
| Weather evidence | `0.8` | Indirect signal |
| ML model prior | `1.0` | From predictor |

### `BeliefState`

```python
@dataclass
class BeliefState:
    asset_id: str
    p_failed: float        # Posterior P(failed) [0, 1]
    is_uncertain: bool     # True if p_failed in [0.25, 0.75]
    confidence: float      # Evidence reliability [0, 1]
    entropy: float         # Shannon entropy — max at p=0.5
    resolved: bool         # True after physical inspection
    resolved_state: str    # 'FAILED' or 'HEALTHY'
```

### Uncertainty zones

| P(failed) | Classification | P3 Action |
|---|---|---|
| < 0.25 | Probably healthy | Skip or low priority |
| [0.25, 0.75] | **UNCERTAIN** | INSPECT has high Value of Information |
| > 0.75 | Probably failed | ACT with high confidence |

## Design Decisions

### Why XGBoost?

1. **Interpretable** — feature importance, SHAP values available
2. **Fast** — training + inference in seconds
3. **Robust** — handles imbalanced classes natively (`scale_pos_weight`)
4. **No black box** — decision engineers can understand which features drive predictions

### Why not a neural network?

GridGuard's uncertainty and impact are safety-critical. Interpretability and
debuggability take precedence over marginal accuracy gains.

### Why not hard-coded probabilities?

The project brief explicitly requires: **"The model must actually be trained
from generated scenario data. No hard-coded probabilities."**

T3's 0.62 failure probability in the demo comes from:
`XGBoost(features of T3 in demo scenario) → 0.624`

not a constant defined in code.
